## Trabajo 1 — Separar Bandeja de EntradasController

**Commit:** `[pendiente]`

### Problema
`EntradasController` (967 líneas) mezclaba el registro de entradas con todo el flujo de la
bandeja del funcionario (listar, ver, archivar, rechazar, anular derivación).

### Archivos modificados
| Archivo | Cambio |
|---|---|
| `app/Http/Controllers/BandejaController.php` | Nuevo. Recibe los 6 métodos de bandeja, código sin cambios |
| `app/Http/Controllers/EntradasController.php` | Se quitan esos 6 métodos (-242 líneas) |
| `routes/web.php` | Las rutas `bandeja/*` apuntan a `BandejaController`; nombres de ruta iguales |
| `app/Models/Derivation.php`, `app/Http/Controllers/ReportController.php` | Comentarios que citaban `EntradasController::derivacion_list()` |

### Solución
Métodos renombrados al moverlos:

| Antes (`EntradasController`) | Ahora (`BandejaController`) |
|---|---|
| `derivacion_index` | `index` |
| `derivacion_list` | `list` |
| `derivacion_show` | `show` |
| `derivacion_archivar` | `archivar` |
| `derivacion_rechazar` | `rechazar` |
| `bandejaDerivationDelete` | `deleteDerivacion` |

Quedan en `EntradasController` los métodos compartidos o propios de la entrada:
`store_derivacion`, `add_derivacion`, `treeAjax`, `delete_derivacion*`. Como los nombres de
ruta no cambian, las vistas no se tocaron.

## Trabajo 3 — Pestaña "Vías" en la bandeja y pestañas con contadores

**Commit:** `[pendiente]`

### Problema
Las derivaciones en las que el funcionario figura como vía (`derivations.via = 1`) se mezclaban
con Pendientes, Urgentes y Derivados. El funcionario vía solo toma conocimiento y archiva (no
puede derivar ni rechazar), pero se le contaban como pendientes: el funcionario con más vías
tenía 3.959 vías por atender metidas dentro de sus pendientes y urgentes.

### Archivos modificados
| Archivo | Cambio |
|---|---|
| `app/Models/Derivation.php` | Scopes `sinVias()` / `soloVias()`; `resumenPara()` excluye vías de pendientes/urgentes y suma `derivados`, `vias`, `vias_total`, `archivados` |
| `app/Http/Controllers/BandejaController.php` | Pendientes/Urgentes/Derivados con `sinVias()`; nuevo caso `vias`; `index()` pasa los contadores |
| `resources/views/bandeja/vias.blade.php` | Nueva. Misma tabla que Pendientes |
| `resources/views/bandeja/browse.blade.php` | Radios reemplazados por pestañas simples con icono y contador; recuerda la última pestaña |

### Solución
- Pestaña **Vías** (icono `fa-signs-post`): lista `via = 1` con `ok` en `NO` o `SI`, misma tabla
  que Pendientes. Las vías archivadas siguen en Archivados.
- La búsqueda de la pestaña Vías usa parámetros enlazados.
- Contadores de las pestañas salen de `Derivation::resumenPara()`: coinciden exacto con lo que
  lista cada pestaña (verificado con el funcionario 1154: 1297 / 640 / 4350 / 774 / 2).

4. Derivaciones: se quitó el campo "id de cargo" que nunca se utilizó.
5. Bandeja de entrada: nueva pestaña "Vías" para los trámites que pasan por el funcionario solo para su conocimiento, separada de pendientes, urgentes y derivados. Las pestañas ahora muestran cuántos trámites hay en cada una.

**Resultado:** El sistema funciona igual para el usuario y el código queda más ordenado y fácil de mantener.
