## Trabajo 1 — Actualización de PHP a 8.3.36 (FrankenPHP en lugar de NGINX Unit)

**Commit:** `[pendiente]`

### Problema
La imagen Docker usaba `unit:1.33.0-php8.2`. NGINX Unit se archivó en octubre de 2025 y ya no recibe parches de seguridad. PHP 8.3.36 corrige dos vulnerabilidades críticas de ejecución remota de código sin autenticación (CVE-2026-109618 y CVE-2026-109619). Se replicó el cambio hecho en SisMark (commit `1564dd5`) y en SysAlmacen.

### Archivos modificados
| Archivo | Cambio |
|---|---|
| `Dockerfile` | `FROM dunglas/frankenphp:1.13.2-php8.3.36-bookworm` (antes PHP 8.2); el build falla si PHP < 8.3.36; permisos para `www-data` (storage, bootstrap/cache, `/data/caddy`, `/config/caddy`); `setcap -r` al binario; `USER www-data`; `CMD frankenphp run`. Se corrigió `custom.ini`: `memory_limit` usaba `>` y borraba la config de OPcache/JIT. |
| `Caddyfile` (nuevo) | Puerto 8000, `auto_https off`, estáticos de `public/` y el resto a `index.php` (`php_server`), `X-Forwarded-For` solo desde rangos privados, log a stdout. |
| `unit.json` (eliminado) | Reemplazado por `Caddyfile`. |

### Solución
FrankenPHP hace lo mismo que Unit con un solo proceso (sirve estáticos y ejecuta PHP). El PHP queda fijo en el tag del `FROM`; para un parche nuevo se cambian el tag y el mínimo del chequeo. El servidor ya no corre como root.

Se verificó con `composer check-platform-reqs --lock` que todas las dependencias (Laravel 10) son compatibles con PHP 8.3.

**Antes:**
```dockerfile
FROM unit:1.33.0-php8.2
...
COPY unit.json /docker-entrypoint.d/unit.json
CMD ["unitd", "--no-daemon"]
```

**Después:**
```dockerfile
FROM dunglas/frankenphp:1.13.2-php8.3.36-bookworm
...
COPY Caddyfile /etc/frankenphp/Caddyfile
USER www-data
CMD ["frankenphp", "run", "--config", "/etc/frankenphp/Caddyfile"]
```

> No se pudo construir la imagen en local porque Docker Desktop no estaba corriendo: falta probar el `docker build`.
> Al corregir `custom.ini`, OPcache con JIT (tracing, 256M) queda activo por primera vez.

**Informe de trabajo — 22/10/2026**

**Actividad:** Actualización de seguridad del servidor del sistema de correspondencia (PHP 8.3.36).

**Problema detectado:**
El servidor donde corre el sistema usaba PHP 8.2 y un componente (NGINX Unit) que ya no recibe actualizaciones de seguridad. Se publicaron dos fallas críticas que permiten ejecutar código en el servidor sin iniciar sesión, corregidas en PHP 8.3.36.

**Detalle de archivos modificados:**
1. Dockerfile: nueva versión de PHP, nuevo servidor web y permisos de usuario sin privilegios.
2. Caddyfile (nuevo): configuración del nuevo servidor web.
3. unit.json: eliminado, ya no se usa.

**Resultado:** El servidor queda protegido contra las vulnerabilidades críticas de PHP y usa componentes con soporte de seguridad vigente.
